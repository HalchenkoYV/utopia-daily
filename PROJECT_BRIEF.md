# Utopia Daily — Project Brief (for Claude Code)

Read this file fully before writing any code. Also read `mockup.html` (design reference) and `article-prompt.md` (content generation prompt) in this folder.

## What we are building

Utopia Daily is a good-news reading site for English learners. Stories are openly fictional, uplifting "real; fake news" set in an optimistic alternate reality. Every story exists in 5 CEFR levels (A1, A2, B1, B2, C1); the reader switches level inside the story. Readers can save unknown words to a personal "My Words" list and write a short retelling of what they read, which AI checks for understanding and grammar.

Audience: learners aged 15–65 worldwide. The entire UI is in English — no other languages anywhere in the interface.

## Stack (keep it simple and stable)

- Next.js (App Router, TypeScript), deployed on Vercel
- Supabase: auth (email + password, plus magic link) and the database for user data
- Story content: JSON files committed to the repo in `content/` (NOT in the database). This is deliberate: stories are generated by a scheduled Claude task that commits new files to GitHub, and Vercel redeploys automatically.
- Retelling check: Google Gemini API (cheap/free Flash model) via a server-side API route. Key in env var `GEMINI_API_KEY`. Never expose it to the browser.
- Styling: plain CSS / CSS modules following `mockup.html` exactly (colors, fonts Fraunces + Inter, level colors, dark mode). No UI kit.

## Content format

One file per story: `content/YYYY-MM-DD/story-N.json` (N = 1..6), matching the JSON schema defined in `article-prompt.md` (`topic_category`, `levels.{a1..c1}.{title, excerpt, body, vocab[]}`). Add a `status` field: `"draft"` or `"published"`. Only `published` stories appear on the site.

Images: for now use the CSS gradient placeholders by topic from the mockup (env, energy, community, culture, food, tech). Real images come later.

## Pages

1. **Home `/`** — exactly like `mockup.html`: header (logo + tagline, YOUR LEVEL selector, search, My Words toggle, Log in / Sign up), feed of day blocks (Today, Yesterday, older days), 6 story cards per block, "Popular" block at the end, footer (Utopia Daily / for English learners / real; fake news / powered by AI). Show the 3 most recent days, then a "Show more days" button.
2. **Story `/story/[date]/[n]?level=b1`** — full text at the chosen level, level switcher with colored underline (not filled), IELTS note under the switcher for every level (A1 below 3.5, A2 3.5–4.5, B1 4.5–5.5, B2 5.5–6.5, C1 7.0–8.0). Clicking any word in the text opens a small popover: definition (from the story's `vocab` if present, otherwise "Save" without definition) + "Add to My Words". Below the text: the retelling box.
3. **My Words** — right sidebar toggled from the header (as in the mockup) + a full page `/words` with the list, delete button, source story link.
4. **Auth** — `/login`, `/signup`. Saving words and submitting retellings require login; reading does not.

The global "YOUR LEVEL" choice is stored in localStorage for guests and in the profile for logged-in users.

## Search

Client-side search over titles, topics and excerpts of loaded stories (as in the mockup). Good enough for launch.

## Popular

For launch: count story views in Supabase (`story_views` table, one row per view, insert from the story page). Popular = most viewed in the last 7 days. If no data yet, show the most recent stories.

## Database (Supabase) — enable Row Level Security on every table

- `profiles` (id uuid = auth.users.id, level text default 'b1', created_at)
- `saved_words` (id, user_id, word, definition, story_path, level, created_at) — unique (user_id, word)
- `retellings` (id, user_id, story_path, level, text, feedback jsonb, created_at)
- `story_views` (id, story_path, created_at) — insert allowed for anyone, no select of individual rows needed beyond an aggregate view/RPC for popular

RLS: users can only read/write their own rows in `profiles`, `saved_words`, `retellings`.

Put the SQL in `supabase/schema.sql` so it can be pasted into the Supabase SQL editor.

## Retelling check (API route `/api/check-retelling`)

Input: story text at the user's level, the level, the user's retelling (limit 1,000 characters). Requires login. Simple rate limit: max 20 checks per user per day.

Ask Gemini to return ONLY JSON:
```
{
  "understanding_score": 1-5,
  "understanding_feedback": "1–2 sentences, level-appropriate English",
  "corrected_text": "the retelling with grammar fixed, meaning unchanged",
  "errors": [{"original": "...", "correction": "...", "explanation": "short, simple English"}],
  "encouragement": "one warm sentence"
}
```
Explanations must match the learner's level (very simple English for A1–A2). Show the result nicely under the retelling box: score, feedback, corrected text with changes highlighted, list of errors. Save the result in `retellings`.

## Environment variables

- `NEXT_PUBLIC_SUPABASE_URL`
- `NEXT_PUBLIC_SUPABASE_ANON_KEY`
- `GEMINI_API_KEY` (server only)

Create `.env.example` with these names. The user will paste real values into `.env.local` and into Vercel themselves — do not ask them to paste keys into the chat.

## Build order (deploy early, then add features)

1. Scaffold Next.js, port the mockup into the home page, generate one day of sample content (6 stories × 5 levels) using `article-prompt.md`, set `status: "published"`. Create GitHub repo `utopia-daily`, push, deploy to Vercel. → The site is online.
2. Story page with level switcher and IELTS notes.
3. Supabase auth + schema + My Words (popover, sidebar, /words page).
4. Retelling check with Gemini.
5. Views + Popular block, "Show more days".
6. Write `SCHEDULED_TASK.md`: the exact instruction for a daily scheduled Claude task that generates 6 new stories for today into `content/<today>/` as `draft`, commits and pushes. Also a short script `scripts/publish-day.mjs <date>` that flips a day's drafts to `published`.

After each step: commit, push, confirm the Vercel deployment works, and tell the user in plain Russian what to check in the browser.

## Content rules (repeat of the prompt, enforce when generating)

Uplifting, fictional places/people only, no real countries/brands/public figures, no health or medical topics or advice, medium playfulness, news style.
